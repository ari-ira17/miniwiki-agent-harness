# Безопасность

- Пароли хранить с Argon2 (или bcrypt, если это отдельно согласовано),
  никогда в открытом виде; секреты и начальные учётные данные брать из env.
  Не помещать их в репозиторий, логи, скриншоты и отчёт.
- Очищать HTML после Markdown-рендера через nh3 с явной политикой тегов,
  атрибутов и URL. Одинаково защищать статью и предпросмотр; проверять XSS.
- Передавать данные в SQL параметрами через ORM или параметризованные запросы;
  не собирать запросы из пользовательских строк.
- Применять серверную авторизацию для каждой операции и каждого канала данных:
  UI, прямой URL, API, поиск, теги и дерево. Скрытие кнопки недостаточно.
  Гость статьи не читает; reader получает только public; редактор не управляет
  пользователями и экспортом; экспорт и управление пользователями — admin.
- Защищать изменяющие формы от CSRF, проверять жизненный цикл серверных сессий
  и параметры cookie. Не допускать удаления или понижения последнего активного admin.
- Проверять входные данные, неизменяемые ASCII-пути и имена файлов экспорта;
  предотвращать выход из каталога и конфликты. Не удалять дочерние статьи
  при удалении родительской. Ошибки не должны раскрывать секреты.

Матрица ролей и договорённости: `docs/ai/PROJECT.md`, ADR-004, ADR-005,
ADR-007–009 в `docs/ai/DECISIONS.md`. Проверяй их тестами по мере реализации.

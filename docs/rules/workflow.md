# Рабочий процесс

1. В начале прочитай инструкции, память и ROADMAP согласно `AGENTS.md`,
   проверь Git и реальные файлы. Не отменяй чужую работу.
2. Для нового этапа сначала покажи план и дождись согласования пользователя.
   Выполняй согласованные задачи последовательно и в пределах проекта.
   При необходимости значимого нового продуктового решения обсуди его;
   в ADR фиксируй только принятые решения с альтернативами и причиной.
3. После каждой задачи запускай применимые проверки и pytest, когда тесты
   приложения существуют. До этого проверяй изменённые документы/навыки и
   явно сообщай, что pytest приложения ещё отсутствует. Не утверждай, что
   команда прошла, если она не запускалась; при ошибке укажи вывод и причину.
4. Не коммить при проваленных проверках; commit и push — только по отдельной
   просьбе. Зависимости согласовывай по `stack.md`. Реальные ошибки агента и
   исправления записывай в GOTCHAS; повторяющиеся превращай в правила.
5. В конце сессии обнови `docs/ai/PROGRESS.md`: сделано, в работе, следующий
   шаг, результаты проверок, ограничения и ожидающие действия. Значимые решения
   отражай в DECISIONS; актуализируй ROADMAP и реестр доказательств.

PROGRESS — краткая актуальная сводка, не дополняемый протокол каждой сессии.
Обновляй существующие разделы, убирай заменённые результаты и устаревшие
статусы. Решения с альтернативами и причинами хранятся как ADR в DECISIONS;
в PROGRESS достаточно ссылки. Подробности проверок — в логах и evidence,
ошибки — в GOTCHAS. Для прежних версий памяти используй историю Git;
не создавай отдельные архивные копии сводки.
Отделяй последние сохранённые проверки от проверок текущей сессии;
не переноси прежние разрешения на commit/push как разрешение новой задачи.

## Сбор доказательств

Агент сам снимает доступные экраны через доступные инструменты сразу после
результата или вызова навыка и до завершения сессии. Проверь каждый реальный
кадр на читаемость и отсутствие секретов; сохрани в `docs/report/screenshots/`.
В `docs/report/evidence.md` укажи путь, содержание, дату, контекст/роль,
состояние рабочего дерева и предлагаемую подпись. Логи проверок сохраняй по
необходимости в `docs/report/logs/`. Схема и снимок экрана — разные материалы.

Перед захватом переключаемых панелей дождись конечного состояния анимации
и проверь положение/направление контролов; для Playwright-снимков допустимо
`animations="disabled"`. Промежуточный кадр не доказывает конечный вид UI.

В колонке «Материал» реестра перечисляй каждый конкретный файл с полным
абсолютным путём в текущем checkout и кликабельной ссылкой. Не заменяй файлы
масками, сокращениями или словами «UI», «логи», «чат». Для ещё не созданного
файла указывай точный планируемый путь и пометку «План, файл ещё не создан»;
его наличие и готовность не подтверждены. При передаче сессии сверяй пути
с файлами; после переноса checkout обновляй абсолютные пути по новому корню.

Если захват нужного экрана недоступен, сразу сообщи пользователю точный кадр,
что должно быть видно, и имя файла; отметь «ожидается ручной снимок» в
`docs/report/evidence.md` и `docs/ai/PROGRESS.md`. Не заменяй реальный снимок
имитацией. Текстовое обещание применить навык не доказывает его вызов.
При завершении перечисли собранные и недостающие материалы. Новую сессию
доказывай только фактическим продолжением в новом чате по PROGRESS.

## Актуальность контейнерных проверок

Compose app не монтирует исходники проекта. После изменений приложения/тестов
пересобери и пересоздай только app перед контейнерными проверками
(`docker compose up -d --build --no-deps app`), сохраняя рабочую БД/volume.
Сверь доступность изменённого файла/поведения внутри app. Успех all на старом
image не подтверждает текущие исходники; такой результат отмечай отдельно.

## Локальная компиляция Python

Для `python3 -m py_compile` в этой среде задавай
`PYTHONPYCACHEPREFIX=/private/tmp/miniwiki-pycache`: системный Python3.9
пытается писать кэш в недоступный ~/Library/Caches. Не расширяй доступ
и не меняй глобальные настройки ради кэша проверки.

## Локальные материалы отчёта и публикация

По решению пользователя весь `docs/report/`, включая evidence.md, логи и
снимки, остаётся локальным и исключён через `.gitignore`. Продолжай собирать
и проверять материалы; исключение из Git не означает их удаление или
завершение отчёта. В свежем клоне эти файлы отсутствуют, а ссылки на них
относятся к локальному комплекту. Резервную копию комплекта нужно хранить отдельно.
`python3 scripts/check_harness.py` проверяет публикуемый харнесс;
`python3 scripts/check_harness.py --with-report` дополнительно требует локальный
реестр evidence.md. Эта проверка не заменяет визуальную проверку снимков.
Коммиты готовь в хронологическом порядке этапов, небольшими тематическими
группами; сообщения — по Conventional Commits без scope согласно AGENTS.md.

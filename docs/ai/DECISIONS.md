# Принятые решения

## ADR-018 — упрощённое дерево дисциплин и доступное создание

Статус: принято по прямому запросу пользователя05.11.2026, дополнение6.6.
Дерево группирует дисциплину как папку с «Основной страницей» и «Лекциями»;
в лекциях только существующие локальные страницы. Пустой список обозначается
«Лекции отсутствуют». Заголовки внутри текста остаются в отдельном оглавлении,
что заменяет предыдущую детализацию sidebar из ADR-017/6.5. Никаких статей
ради группировки не создаётся; прочие пользовательские страницы не теряются,
ограничение SQL scope действует до построения групп/названий.
Admin/editor получают явный вход в создание страницы; reader/guest — нет.
После входа открывается главная «Учебные дисциплины», не список /pages.
Создатель хранится в БД/API, визуальная подпись автора убирается; последний
редактор/время остаются. Пункты «Курсы», «КАТАЛОГ КУРСОВ» и последующая подпись «КАТАЛОГ» удаляются.
Кнопка меню — светло-серая круглая стрелка снизу слева, направление отражает
состояние, открытие доступно клавиатурой. TOC главной/практикума одинаково шире;
заголовок главной при скрытом sidebar совпадает с текстом карточки бакалавриата.
Шрифт сверён по реальному DOM wiki.pmifi.ru: Roboto16/24/400, h2 32/38.4/500,
letter-spacing normal; локальные шрифты сохраняются, глобальные не устанавливаются.
Альтернативы: дерево всех заголовков, создание через скрытый /pages/new,
постоянная кнопка-бургер в шапке. Причина: прямые UX-уточнения пользователя.
Последующее прямое уточнение: sidebar группируется по ступени и курсу:
Бакалавриат1–4, Магистратура1–2. Ветки дисциплин на 3 курсе используют полные
заголовки соответствующих страниц по последнему уточнению пользователя.
Это виртуальная навигация без новых страниц; основные
страницы/лекции и их реальные названия/пути остаются внутри веток. Пустые годы
показываются папками, не вымышленными материалами.
Ещё одно уточнение: в редакторе верхняя полоса содержит только «РЕДАКТОР MARKDOWN».
Отдельная карточка возврата убирается; возврат остаётся обычной ссылкой у формы,
форма становится одноколоночной в обоих состояниях меню. Поля/предпросмотр/
POST/CSRF/права остаются. Альтернатива: прежняя карточка TOC/крупный заголовок;
изменено по прямому скриншоту и просьбе пользователя.
Последующее уточнение практикума: его заголовок с открытым sidebar выравнивается
по внешнему левому краю TOC, с закрытым — по внешнему левому краю карточки
статьи. Это отдельное правило от главной, которая выравнивается по тексту
внутри карточки бакалавриата. Проверка ширин1000/1440/1920.
Данные4аккаунтов/3статей и авторизационные гарантии сохраняются. Экспорт — этап7.

Уточнение 06.11.2026: статьи дисциплин и лекций используют общую сетку
заголовка и карточки текста в обоих состояниях бокового меню. Это заменяет
прежнее особое выравнивание заголовка Практикума. Технические пути убраны
из шапки статей и результатов поиска; URL и поле пути редактора сохранены.
Гость на `/` перенаправляется на `/login`; каталог открывается с сессией.
Оглавления статей используют ширину Практикума 220 px на настольных экранах.
На мобильных оглавление занимает ширину карточки статьи.
Главная использует ту же сетку заголовка, что статьи. «Учебные дисциплины»
выравниваются по внешнему левому краю карточки каталога в обоих состояниях
меню. Это заменяет прежний отдельный отступ для заголовка главной.

## ADR-017 — профили, последний редактор и учебный каталог

Статус: принято пользователем05.11.2026, обновлённый план согласован в чате.
Имя и фамилия обязательны, непусты после trim; отдельные поля, логин остаётся
идентификатором входа. Admin задаёт и редактирует имена. Старые аккаунты нельзя
заполнять вымышленными именами: реальные данные получены пользователем,
передаются локально через env/подготовку миграции. Само изменение имён не
меняет роль и не требует отзыва сессии. Видимые ID/«вы» из списка убираются.
Создатель страницы и последний редактор — разные связи. API берёт редактора
из сессии, не из JSON; учитываются сохранения текста, заголовка и тегов/public.
Карточка показывает имя/фамилию и дату, старым изменениям редактор не
приписывается. Удаление аккаунта сохраняет статью и обнуляет ссылку.
Главная — краткое описание и каталог дисциплин по курсам. Реальные материалы
имеют NLP и практикум5семестра; прочие пункты возвращают на главную. Боковое
дерево раскрывается, хлебные крошки и печать/поделиться отсутствуют.
Курсы сохраняют структуру, названия, списки и таблицы источников. Только
«Лекция1.CRISP-DM» ведёт в указанную презентацию Google; предобработка — на
локальную вложенную страницу, все другие исходные ссылки — на свой курс.
Лабораторные дополнительно не импортируются (заменяет первоначальную идею).
Предоставленный пользователем текст лекции переносится без сокращений,
код только отображается; изображения не приложены, схема содержит4этапа.
Удаляются4согласованные /demo статьи;2курсовые сохраняются. По отдельному
указанию reader «аристова» удалён, создаётся новый reader ivanov с данными,
предоставленными пользователем; пароль только в локальном.env.
Альтернативы: необязательные имена с fallbackлогином, один author длясоздания
и правок, перенос всех лабораторных, внешние ссылки на все материалы.
Причина: прямые уточнения пользователя и достоверная атрибуция действий,
навигируемый учебный пример без расширения до экспорта/истории версий.
Экспорт остаётся этапом7. Новые зависимости не планируются; commit/push запрещены.
Уточнение пользователя05.11: расширить основной текст лекции на desktop;
уменьшить боковые колонки/отступы, сохранить читаемость и адаптивность.
Дополнение пользователя05.11: убрать пункт «Страницы» из меню, сохранив
маршруты поиска/тегов/CRUD; добавить скрытие/возврат бокового дерева. При
скрытии оглавление/статья расширяются, внешние отступы и максимальная ширина
сохраняют читаемость. Альтернатива: постоянно открытое меню; изменено по
прямому запросу пользователя. Новые reader/editor нужны для ролевой демонстрации.
По следующему прямому уточнению: дерево различает папки без страницы, документы
и подразделы документа отдельными значками. Документы раскрываются до заголовков,
ссылки подразделов используют якоря общего рендера. Права фильтруют не только
названия страниц, но и заголовки; REST-контракт дерева сохраняется. Альтернатива:
дерево только страниц с отдельным оглавлением; расширено по примеру пользователя.
Уточнение реализации: локальный docs/report не включается в Dockercontext
и Ruff; предоставленная Markdown-лекция хранится как данные с неизменяемыми
примерами, для её файла допустимо точечное исключение форматтера. Python-код
приложения остаётся полностью проверяемым. Причина: воспроизводимость свежего
клона без локального отчёта и сохранение предоставленного материала.

## ADR-016 — аутентификация и роли спринта 3

Статус: принято пользователем 04.11.2026, план согласован в текущем чате.
Решение: серверные сессии PostgreSQL, случайный токен с хранением хеша,
абсолютный срок 8 часов; cookie HttpOnly/SameSite=Lax и настраиваемый Secure
для HTTPS при сохранении локального HTTP. CSRF защищает вход, выход и
изменяющие запросы HTML/JSON API. Выход отзывает сессию; смена пароля,
роли, отключение или удаление пользователя отзывают его сессии.
Гость статьи не читает: HTML перенаправляет на вход, API возвращает 401.
Reader читает только статьи с тегом public; скрытые статьи возвращают 404.
Editor/admin читают всё, выполняют CRUD/preview; пользователи — только admin.
Проверки выполняются на сервере, фильтрация всех производных данных — в SQL
до подсчётов и пагинации. Новым статьям присваивается реальный автор.
Тег public — источник видимости; прежнее поле is_public остаётся совместимым
представлением API. Старым is_public=true добавляется тег public миграцией;
имеющийся тег public тоже означает доступ reader. Противоречивые явно
переданные значения отклоняются; изменение только is_public изменяет тег.
Admin создаёт пользователей, задаёт роль/пароль, отключает и удаляет; без
саморегистрации. Последний активный admin защищён, включая конкуренцию.
Альтернативы: JWT, гостевое чтение, независимые is_public и public, удаление
поля API. Причина: ранее выбранные серверные сессии и отсутствие регистрации,
однозначное выполнение требования о теге и совместимость существующего API.
Реализовано и проверено 05.11.2026: 85 pytest/Ruff, 3 E2E, миграции,
smoke и независимый обзор. Формы явно используют POST даже без JavaScript;
JSON-перехват остаётся основным UI. Общая trim/casefold-нормализация применяется
к новым именам и поиску совпадений bootstrap/создания/входа; старые имена и
пароли не перезаписываются. Неоднозначные старые варианты требуют точного
имени; новые коллизии запрещены. Экспорт — этап 7.

## ADR-015 — поиск, теги и навигация спринта 2

Статус: принято пользователем 04.11.2026, план согласован в чате.
Решение: регистронезависимый поиск подстроки в title или исходном Markdown,
запрос до 200 символов; `%` и `_` считаются обычными символами. Пустой запрос
показывает список; один точный фильтр по тегу сочетается с поиском и пагинацией.
До 20 тегов на страницу, до 32 символов на тег, trim и удаление дублей без
учёта регистра. Теги входят в создание, чтение и обновление страницы.
Редактор использует запятые как разделитель; запятые и управляющие символы
в самом теге отклоняются, чтобы редактирование сохраняло исходный набор.
GET /api/pages расширяется q/tag; GET /api/tags и GET /api/navigation/tree
возвращают доступные теги и дерево. API и HTML используют общие сервисы.
Дерево сохраняет виртуальные ветви; отсутствующий предок в крошках не ссылка.
Оглавление h1–h6 имеет стабильные уникальные якоря, включая повторы заголовков;
рендер статьи и preview остаётся единым и очищенным.
Общая точка ограничения видимости применяется до подсчётов и пагинации,
построения дерева, тегов и крошек. Подключение входа и проверка всех ролей —
этап 6; наличие точки фильтрации не означает готовую авторизацию.
Демонстрационные страницы добавляются отдельной повторяемой командой без
перезаписи существующих данных. Палитра и выбранная компоновка сохраняются.
Альтернативы: полнотекстовый поиск со словарями PostgreSQL, несколько тегов
в одном фильтре, клиентский индекс и отдельный клиентский Markdown-рендер.
Причина: согласованный объём MVP, предсказуемый поиск и единая фильтрация
для следующего спринта без новых зависимостей и преждевременной системы ролей.

Уточнение ADR-010 / ADR-015, 04.11.2026: пользователь повторно указал,
что нужен аналог wiki.pmifi.ru с тем же шрифтом в согласованных иных цветах.
Живой осмотр DOM и снимка подтвердил Roboto в интерфейсе и статье, 16/24px
для основного текста, шапку 64px и боковую панель 256px. Решение: локальный
Roboto с кириллицей из Google Fonts (лицензия OFL хранится рядом), более
плотная полоса заголовка, сохранение структуры образца и собственной палитры.
Альтернатива: прежний системный шрифт либо внешний CDN Google Fonts.
Причина: явное требование одинакового шрифта и независимость локального UI
от внешней загрузки. Это статический ресурс, новая Python/JS-зависимость не нужна.

## ADR-014 — контракты страниц и Markdown спринта 1

Статус: принято пользователем 04.11.2026, план и зависимости согласованы в чате.
Решение: канонический путь `/docs/nlp`, без нормализации и конечного `/`;
сегменты `[a-z0-9]+(?:-[a-z0-9]+)*` до 64 символов, путь до 512.
Путь неизменяем, виртуальные ветви допустимы, удаление без каскада.
Title: 1–200 непустых символов; Markdown до 200000; is_public=false;
UTC-время создания/изменения. Автор неизвестен до входа, не bootstrap admin.
JSON API: POST/GET `/api/pages`, GET/PATCH/DELETE `/api/pages/{id}`,
GET `/api/pages/by-path?path=...`; POST `/api/markdown/preview` возвращает HTML.
Создание 201, удаление 204, остальные успехи 200; ошибки 404/409/422,
неизвестные поля и path в PATCH запрещены. Список постраничный.
Добавить markdown-it-py (рендер) и nh3 (очистка) с фиксацией в uv.lock;
общий серверный конвейер статьи и preview, явные теги/атрибуты/URL.
Альтернативы: нормализация путей, изменяемый path, клиентский рендер,
Python-Markdown, отдельный multipart-парсер для форм.
Причина: предсказуемые пути и единое безопасное отображение; формы могут
отправлять JSON без новой зависимости. До этапа 6 — только локальная среда,
без имитации аутентификации и прав; поиск/теги/дерево остаются этапом 5.

Дата записей: 03.11.2026. Основание — ответы пользователя в текущем чате.
Это начальная фиксация ADR, а не доказательство использования ещё не созданного навыка.

Версии в uv.lock: markdown-it-py 4.2.0, nh3 0.3.7; mdurl 0.1.2 —
транзитивная зависимость markdown-it-py. Проверки совместимости — в логах этапа 4.

## ADR-002 — Python и серверный стек
Статус: принято.
Альтернативы: Python 3.11/3.14; Django/Node.js; SPA React/Vue; SQLite.
Решение: Python 3.12, FastAPI, PostgreSQL, Jinja2, HTMX.
Причина: явный выбор пользователя; компактный серверный UI и практика PostgreSQL.
Последствия: два сервиса Compose; HTML и JSON используют общую бизнес-логику.

## ADR-003 — данные и миграции
Статус: принято.
Альтернативы: ручные SQL-запросы и миграции; SQLAlchemy + Alembic.
Решение: SQLAlchemy, Alembic, psycopg; синхронная работа с БД.
Причина: связанные модели и последовательное изменение схемы по спринтам.
Последствия: проверять миграции, запускать интеграционные тесты на PostgreSQL;
синхронные операции не выполнять блокирующим кодом внутри async-маршрутов.

## ADR-004 — Markdown и безопасность
Статус: принято.
Альтернативы: Python-Markdown; отдельный клиентский рендер.
Решение: markdown-it-py → HTML → nh3, общий конвейер статьи и предпросмотра.
Причина: одинаковое отображение и обязательная очистка пользовательского HTML.
Последствия: явная политика тегов/атрибутов/URL и тесты XSS; рендер не заменяет санитайзер.

## ADR-005 — проверки и аутентификация
Статус: принято.
Альтернативы: только ручная проверка; JWT вместо серверных сессий.
Решение: pytest/httpx, Ruff, несколько Playwright-сценариев; argon2,
серверные сессии с cookie, CSRF-защита изменяющих форм.
Причина: проверяемое выполнение ТЗ и простая модель доступа для серверного UI.
Последствия: тесты прав через API и UI, жизненного цикла сессий и CSRF;
точные пакеты и версии инфраструктурных зависимостей обосновать перед добавлением.

## ADR-006 — навыки
Статус: принято.
Альтернативы: минимальные 3–4 навыка; 6 тематических навыков.
Решение: add-wiki-endpoint, security-review, session-handoff,
webapp-testing, systematic-debugging, адаптация grill-with-docs.
Причина: покрыть создание API, безопасность, передачу, UI, отладку и решения.
Последствия: не менее двух навыков имеют scripts/ или references/;
внешние источники, лицензии и commit фиксируются после проверки.
grill-me сам не сохраняет состояние; адаптация grill-with-docs записывает
согласованные ADR в этот файл. Отдельный design-interview не добавляется.
При адаптации проверить зависимые процедуры grilling/domain-modeling,
не копировать неработающие вызовы чужой среды.

## ADR-007 — роли и пользователи
Статус: принято.
Альтернативы: анонимное чтение public; только авторизованные пользователи.
Решение: без гостевого чтения; admin/editor/reader согласно PROJECT.md.
Причина: reader обязателен по ТЗ, дополнительный гостевой доступ пользователю не нужен.
Последствия: public означает доступ reader после входа; фильтровать все каналы чтения.
Управление пользователями — небольшой экран admin без саморегистрации;
последнего активного admin нельзя удалить или понизить.

## ADR-008 — пути
Статус: принято.
Альтернативы: кириллические пути, изменение путей/ветвей, каскадное удаление.
Решение: уникальные пути из ASCII-сегментов; не меняются после создания;
виртуальные промежуточные ветви; удаление только выбранной статьи.
Причина: предсказуемая навигация и защита от случайной потери потомков.
Последствия: валидировать сегменты и конфликты; заголовки/тексты не ограничены ASCII.

## ADR-009 — экспорт
Статус: принято.
Альтернативы: чистые .md без метаданных; Markdown с YAML-frontmatter.
Решение: ZIP всех страниц, путь /docs/nlp → docs/nlp.md;
в начале YAML с title и tags, далее исходный Markdown.
Причина: пользователь выбрал сохранение заголовка и тегов для переноса данных.
Последствия: только admin; безопасная сериализация YAML, корректный UTF-8,
защита путей; /docs/nlp и /docs/nlp/topic могут сосуществовать;
импорт и совместимость с конкретной сторонней wiki не обещаются.

Уточнение 06.11.2026: согласованы GET /api/export и GET /export через общий
сервис и проверку роли, файл `miniwiki-export.zip`, общий ответ 409 при
невалидном сохранённом пути или коллизии. Пользователь выбрал точное
соответствие путей вместо экранирования Windows-имён через `~`. Ограничение
распаковки таких имён на Windows описано в API; пути страниц не меняются.

## ADR-010 — интерфейс
Статус: принято.
Альтернативы: точная копия Wiki.js; упрощённый интерфейс по его компоновке.
Решение: компоновка кафедральной wiki; #5D5958 + #FFFFFF + #622128.
Причина: выбранные пользователем образец и палитра.
Последствия: #5D5958 — приближение по изображению; проверять контраст,
не использовать ошибочно введённый #180403; не переносить все функции Wiki.js.

## ADR-011 — доказательства
Статус: принято.
Альтернативы: ручной сбор перед отчётом; сбор агентом по ходу работы.
Решение: агент сохраняет доступные реальные скриншоты и логи по этапам,
регистрирует их в docs/report/evidence.md; при недоступном захвате сразу
сообщает пользователю точный кадр, имя файла и сохраняет ожидающее действие.
Причина: не потерять реальные вызовы навыков и упростить подготовку отчёта.
Последствия: не считать текстовое заявление доказательством вызова навыка;
не включать секреты и не имитировать снимки.

## ADR-012 — инфраструктура спринта 0
Статус: принято пользователем 03.11.2026, план этапа 3 согласован в чате.
Решение: uv и uv.lock для воспроизводимого окружения Python 3.12;
uvicorn как ASGI-сервер FastAPI; pydantic-settings для проверки env;
argon2-cffi для согласованного Argon2; psycopg[binary] как драйвер PostgreSQL.
Альтернативы: pip-tools/Poetry, ручной разбор env, bcrypt, сборка libpq/psycopg.
Причина: компактная контейнерная сборка, проверяемая конфигурация и пароли,
отсутствие глобальных установок. Версии фиксируются в pyproject.toml/uv.lock
после разрешения совместимости; согласованные пакеты будущих этапов не
добавляются до необходимости.
PostgreSQL 17; Compose app/db, именованный volume, без опубликованного порта БД,
приложение на 127.0.0.1:8000. Миграции выполняются перед сервером.
Следствия: локальный каркас без завершённой аутентификации; bootstrap admin
не заменяет систему доступа. Полная авторизация остаётся этапом 6.
GET /health: 200 {"status":"ok"} при доступной БД,
503 {"status":"unavailable"} при отказе; без деталей исключений и секретов.
GET / показывает только служебную оболочку; пользовательских статей пока нет.

Версии разрешены в uv.lock на этапе 3: Alembic 1.20.1,
argon2-cffi 25.1.0, FastAPI 0.162.0, httpx 0.28.1, Jinja2 3.1.6,
Playwright 1.64.1, psycopg/psycopg-binary 3.3.7, pydantic-settings 2.16.2,
pytest 8.4.2, Ruff 0.17.3, SQLAlchemy 2.0.55, uvicorn 0.54.0.
uv в Docker — 0.9.13. Это результат разрешения зависимостей, не отдельное
утверждение прохождения проверок; фактические проверки регистрируются в PROGRESS.

## Уточнение ADR-010 — компоновка по референсу

03.11.2026 пользователь согласовал исправление оболочки этапа 3 после
сравнения со скриншотом кафедральной wiki. Прежняя минималистичная компоновка
признана слишком свободной интерпретацией выбранного ориентира.
Решение: плотная полноширинная шапка #5D5958, постоянная боковая панель
#622128, светлая полоса заголовка, оглавление слева от основной области,
карточки и отступы ближе к референсу; адаптация для мобильного экрана.
Альтернатива: сохранить минималистичную оболочку. Причина изменения:
согласованный ориентир требует более близкой структуры. Палитра остаётся
выбранной; поиск/вход не имитируются, их функции реализуются на своих этапах.

## ADR-013 — локальный отчёт и последовательность публикации

Статус: принято пользователем03.11.2026.
Решение: весь docs/report/ исключён из Git; материалы продолжают собираться
локально. Публиковать код, правила, навыки, требования и память небольшими
тематическими коммитами в порядке выполненных этапов и зависимостей.
Альтернативы: публиковать отчёт целиком/частично; один общий коммит.
Причина: пользователь отделил материалы отчёта от публикуемого репозитория
и запросил раздельную хронологическую историю. Последствия: в свежем клоне
нет реестра/логов/снимков, ссылки на них локальные; нужна отдельная резервная
копия. Базовый валидатор не требует отчёта, --with-report проверяет реестр.
Последовательность коммитов согласована в чате; пользователь явно разрешил
commit/push03.11.2026. Переписывание истории и подделка дат не разрешены.

Уточнение03.11.2026: сообщения коммитов без scope в скобках, например
`docs: document startup configuration and local checks`. Пользователь затем потребовал удалить служебный файл плана публикации
и его исключение из Git; последовательность коммитов остаётся согласованной в чате.

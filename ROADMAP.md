Источник и полная матрица: [ASSIGNMENT.md](docs/requirements/ASSIGNMENT.md).

- Стек: Python 3.12, FastAPI, PostgreSQL, SQLAlchemy/Alembic/psycopg,

  PROGRESS, DECISIONS, GOTCHAS; >=3 навыка, >=2 со scripts/ или references/.
- Skills: корректные name/description в YAML, описание назначения и триггеров;
  тело желательно <=500 строк. Выбраны 6 навыков, см. ADR-006.
- Пароли argon2/bcrypt, очистка HTML, параметризованный SQL, секреты из env.

  что pytest приложения ещё не существует. После появления тестов — не пропускать.
- Не менять файлы вне задачи; не делать commit/push без просьбы;
  не коммитить при проваленных проверках. Новые зависимости обосновывать в ADR.
- В начале читать PROJECT/PROGRESS, в конце обновлять PROGRESS;
  ошибки агента записывать в GOTCHAS, повторяющиеся превращать в правила.
- MVP: docker compose up --build; /health; начальный admin из env при отсутствии;
  CRUD иерархических страниц; Markdown с предпросмотром; поиск заголовка/текста;
  теги/дерево; auth и 3 роли; reader только public; admin-only экспорт .md;
  документированный REST API.
- Без гостевого чтения, регистрации и перемещения путей; экспорт ZIP + YAML title/tags.
- Не менее 3 навыков реально продемонстрировать, сохранить снимки;
  фактически показать продолжение в новом чате по PROGRESS.
- Скриншоты агент делает сам, если захват доступен; иначе сразу сообщает точный
  ручной кадр и фиксирует ожидание в PROGRESS и evidence.md.
- Отчёт: введение, 4 подраздела по ТЗ, заключение с ошибками/обходами/знаниями/
  улучшениями, только цитируемые источники; соблюсти нормоконтроль.
- Подпись, загрузка в ЭК и принятие преподавателем — отдельные действия пользователя.
- Все изменения только внутри проекта; никаких глобальных установок и настроек.

## Рабочие соглашения плана

Восемь этапов соответствуют STAGE-PROMPTS.md. Внутри — небольшие задачи
для последовательных запусков coder; одновременно двух писателей нет.
Главный агент согласует план, проверяет результат, обновляет память;
reviewer выполняет независимую проверку завершённых этапов/итога.

### Роли агентов

| Роль | Ответственность | Когда используется |
|---|---|---|
| Главный агент | Общение с разработчиком, согласование, постановка задач, сверка результатов, память и доказательства | Каждый этап |
| explorer | Исследование репозитория, документации и внешних навыков; краткая сводка без изменений исходников | Перед задачами с неизвестными фактами; особенно проверка внешних навыков в 2.3 и нормоконтроля в 8.2 |
| coder | Реализация одной согласованной задачи, необходимые проверки и отчёт об изменениях | Шаги 2–7; исправления по итогам приёмки |
| reviewer | Независимая проверка результата относительно требований и критериев | Проверка этапов и итоговая приёмка; код не меняет |

explorer подключается по необходимости, а не для повторного исследования уже
подтверждённых фактов. Главный агент передаёт каждому подагенту конкретные границы
задачи и исходные требования. Исследование и проверка могут идти параллельно
с независимой работой, но одновременно не более двух подагентов и одного писателя.
Эти роли описывают порядок делегирования; они не заменяют проектные Skills.

главный агент организует захват приложения и чата через доступные инструменты.

  и имя файла; записать «ожидается ручной снимок» в evidence.md и PROGRESS.md.
